Building this customer support agent taught me that the hardest part of working with AgentCore isn't writing the Python, it's getting all the moving pieces (Gateway, Memory, Knowledge Base, Code Interpreter) to actually agree with each other in the same region and speak the same protocol.
One design decision I'm genuinely happy with is how the MemoryHook retrieves customer context and prepends it directly to the incoming user message, rather than trying to rebuild the system prompt on every turn. Strands' hook events (MessageAddedEvent and AfterInvocationEvent) made this clean: the retrieval and the saving each live in their own method, so the agent's reasoning loop never has to know memory exists at all. It just sees a slightly richer message.
The biggest challenge caught me off guard. When I tested cross session memory, the agent correctly recalled that I prefer concise responses, but flatly refused to say my name back to me, claiming it "didn't have access to personal identification details for security reasons." Nothing in my code blocked that. The model itself decided a name looked like sensitive data and got overly cautious, even though I was the one who had shared it minutes earlier. I had to explicitly tell the system prompt that remembered facts in the "Customer Context" block are things the customer already gave freely, and that repeating them back is expected, not a privacy risk. It was a good reminder that guardrails baked into a foundation model can misfire in directions you didn't ask for, and that prompt engineering sometimes means undoing caution rather than adding it.
For production, I'd want to harden the failure paths further. The loyalty discount tool already falls back to a simplified calculation if the Code Interpreter sandbox is unavailable, and the knowledge base tool degrades gracefully if the ID is missing, but a real deployment would need retries on the Gateway's MCP connection, tighter IAM scoping instead of the broad auto-created execution role, and closer monitoring of OpenSearch Serverless costs, since it kept running (and billing) the entire time I was building, whether I was actively testing or not.
